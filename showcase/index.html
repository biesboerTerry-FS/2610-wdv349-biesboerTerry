03 · Admin Panel

One admin.
Every route guarded.

The panel is intentionally single-administrator: one seeded account, a JWT, and an authenticate middleware in front of every admin route.

Single accountSeeded from environment variables
  • JWT in localStorage keeps the session across refreshes.
  • Bearer token on every /api/admin/* request.
  • 401 handling clears the token and returns to login.
  • No secrets in source: email, password, and JWT_SECRET live in .env.
server/src/routes/admin.jsguard
router.use(authenticate);

router.get("/dashboard", dashboard);
router.get("/meta", (req, res) => {
  res.json({ success: true, data: buildAdminMeta() });
});
Intentional scope: one account, no coach roles. The goal is a reliable admin slice, not a permissions system.

05 · Retrospective

What broke,
what stuck, what's next.

The honest version: the app is a working alpha, not a finished product. The gaps are known, and the next slice is scoped.

01

Challenges

  • A 168 MB archive plus tracked node_modules blocked the push.
  • A duplicate app tree and broken gitlink had to be removed.
  • CORS, Vite ports, and Atlas database naming caused avoidable confusion.
02

What I learned

  • Secret and generated-file hygiene belongs in .gitignore before the first commit.
  • Schema metadata can drive an entire admin UI.
  • Test the production build, not only the dev server.
03

Limitations

  • Most public content pages still read local data; forms and admin are wired to the API.
  • Single admin, no roles or audit log.
  • Placeholder photos/PDFs, no automated tests, no production deploy yet.
04

Next steps

  • Deploy frontend + API with environment secrets.
  • Wire remaining public content to the API; add API + form tests.
  • Accessibility and image optimization; fix logo contrast on cream; prop docs.
Milestone 5 thesis: ship the thin slice end to end, then widen it — deploy first, then replace local page data with API reads.
